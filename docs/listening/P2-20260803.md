### Read this before judging drive (RC2, user-mandated — restated verbatim)

`TriodeStage` is a **static waveshaper**: one memoryless input-voltage → output-voltage curve, no
state carried between samples, therefore no bias drift, no coupling-cap high-pass behaviour, no
cathode-bypass corner interacting with signal level, no thermal settling. **The chain is explicitly
not a voicing reference for drive feel.** Judge item 12 for artifacts and not for whether the amp
"feels" right. Drive-feel conclusions are deferred until a dynamic stage lands in P3+.

## 1. THE `couplingStrength` DECISION

**What it decides.** ADR 0006 ships `couplingStrength = 0.35`. ADR 0007 D4 makes that
**provisional** and reserves the choice for this session. Whatever you write in §1.4 is the shipped
default; P2.9 must not lock it by passing (D4), and if this section is left blank the exit document
records the value as still provisional.

**Why it is a judgement and not a measurement.** The setting buys sympathetic richness and costs
pitch integrity, and both directions are measured. Nothing in the numbers says where the trade
should sit.

### 1.1 What coupling buys — sympathetic richness

Play **`02_open_chords__coupling*__cv2_s….wav`, section B (21.0–29.2 s)**: the low E held under
twelve staccato notes. Six files, in this order:

| render | `couplingStrength` | why this value is in the set |
|---|---|---|
| `coupling000` | 0.00 | the decoupled control. Without it "less coupling" has no zero, and `bridgeOutput()` is identically 0 here by construction. |
| `coupling010` | 0.10 | ADR 0007 D4's own low anchor: **beat depth 10.08 dB**. |
| `coupling020` | 0.20 | the highest value measured **not** to mode-lock at the sustain material (25.045 cents of separation survive). |
| `coupling030` | 0.30 | where the two string materials **disagree**: 0.003 cents at the sustain material, 25.14 at the default one. |
| `coupling032` | 0.32 | the highest **default-material** value measured not to lock (25.18 cents). |
| `coupling035` | 0.35 | the provisional default. Locks at **both** materials. |

Every value is a measured boundary point; none is a round number chosen for tidiness.

**Beat depth falls as coupling rises** — 10.08 / 3.59 / 2.28 / 1.62 dB at 0.1 / 0.35 / 0.5 / 1.0
(ADR 0007 D4). So the richest *beating* is at the low end, and what the high end adds is transfer,
not shimmer. Measured on these six renders, whole-section RMS:

| section | 0.00 | 0.10 | 0.20 | 0.30 | 0.32 | 0.35 |
|---|---|---|---|---|---|---|
| A, the strummed chords (0.2–20.5 s) | −28.31 | −28.96 | −29.44 | −29.84 | −29.91 | −30.01 dBFS |
| B, the sympathetic section (21.0–29.2 s) | −31.63 | −31.91 | −32.16 | −32.39 | −32.43 | −32.50 dBFS |
| the 2 s tail (44.0–46.0 s) | −101.70 | −106.96 | −110.13 | −108.53 | −109.21 | −110.98 dBFS |

More coupling is **quieter and shorter**, monotonically, all the way down the ladder. That is the
bridge doing its job — energy leaving the strings is energy the strings no longer have — and it is
the other half of the trade nobody usually states.

**Pass looks like:** one value where the instrument reads as an instrument — the held string
answering the notes above it, audibly, without the answer sounding like an effect and without the
chords going short.
**Fail looks like:** no audible difference across the ladder (which would mean the bridge is not in
the loop — check `coupling000` against `coupling035` first, and if *those* are the same, stop and
file it), or every value sounding wrong in the same direction.

### 1.2 What coupling costs — pitch integrity, the near-unison pair

This is the case ADR 0007 D5 criterion (4) is about, and the one this session exists to settle.

Play **`02_open_chords__unison*__cv2_s….wav`, section C (30.0–40.0 s)**. Two halves:

- **30.0–36.0 s — both strings held.** MIDI 45 on string 1 and MIDI 46 on string 0, with the
  instrument's own per-string tuning offsets (`stringTuningOffsetCents1` = +25,
  `stringTuningOffsetCents0` = −50) bringing them to **111.60 Hz and 113.22 Hz — 25.00 cents apart**.
- **36.6–40.0 s — string 0 alone**, with string 1 resting near-unison beside it. This is the *purely
  sympathetic* case, which ADR 0007 D7.0 calls "the ordinary one" and which locks at the same
  ceiling.

**Why the MIDI reads a semitone.** `NoteAllocator`'s invariant is that at most one string owns a
given (channel, note), and a guitar unison is always the same MIDI note — so two simultaneous
note-ons for one note are a retrigger of one string, not two strings at one pitch. The two ways out
are per-note channels (the P5 MPE seam, which any host that rewrites the channel on a clip would
silently undo, so the phrase would not survive the live replay step 2 asks for) and the instrument's
own ±50-cent tuning offsets. This uses the second. **What sounds is a 25-cent pair on strings 0 and
1**, which is the configuration under test.

**Measured on these six renders** — FFT over 31–36 s, peaks inside 109–116 Hz:

| render | coupling | what survives | separation |
|---|---|---|---|
| `unison000` | 0.00 | 111.603 Hz @ −0.3 dB, 113.205 Hz @ 0.0 dB | **24.677 cents** |
| `unison010` | 0.10 | 111.626 @ −1.8, 113.205 @ 0.0 | **24.322 cents** |
| `unison020` | 0.20 | 111.671 @ −6.8, 113.205 @ 0.0 | **23.612 cents** |
| `unison030` | 0.30 | 113.182 only | **ONE PEAK — locked** |
| `unison032` | 0.32 | 113.182 only | **ONE PEAK — locked** |
| `unison035` | 0.35 | 113.182 only | **ONE PEAK — locked** |

Two things to notice, because they change what you are listening *for*:

- **The lock is progressive, not a step.** The lower string does not vanish at a threshold; it is
  absorbed — −0.3, −1.8, −6.8 dB and then gone. So the question at 0.20 is not "did it lock" (it did
  not) but "is a partner 6.8 dB down still the chord you played".
- **In this configuration the boundary sits between 0.20 and 0.30**, which is *lower* than the
  0.32–0.35 boundary D7.0 measured on two isolated strings. That is not a contradiction — this is a
  six-string instrument with four other strings resting at their open pitches, all of them in the
  same loop, which is a more strongly coupled system — but it means **the ceiling this session can
  defend may be lower than D7.0's table suggests.** Both measurements now live in the ADR, labelled
  by topology and deliberately not reconciled into one number: **ADR 0007 D7.0** is the isolated
  pair, **D7.1** is the instrument you are about to listen to.

**Pass looks like:** a value where the pair still reads as two strings a hair apart — the sound a
12-string course makes, or a guitar that wants tuning — rather than one string.
**Fail looks like:** the detuned partner disappearing into the other string. That is an instrument
that will not stay where the tuner put it.

### 1.3 The two questions are the same measurement

D5 ties them: mode-locking is a coupling phenomenon, so **the range ceiling and the default are one
choice**. If §1.4 lands below 0.35, the Normal range's coupling ceiling (§2) must come down with it,
and ADR 0007 D7 must be re-derived rather than edited. If it lands *above* 0.35 the `[tuning]` grid
gate fails by design (`kBridgeNormalCouplingMax` is a literal, and the gate asserts the shipping
default lies inside the range) — that failure is the design working, not a regression.

## 2. THE PROVISIONAL NORMAL RANGE — criterion (5)

**State it plainly, because it is the thing this session inherits:** ADR 0007 D7 declares
`couplingStrength` 0.00–0.35, `bridgeResonanceHz` 20–330 Hz, `bridgeDamping` 0.15–1.00. **That box
was derived from criterion (1) — the ±2-cent tuning bound — alone.** Criterion (4) was measured at
its coupling ceiling and **fails** there (D7.0). So **the provisional default currently sits outside
a criterion-complete Normal range**, and if you lower the default in §1.4 the ceiling likely moves
with it.

Criterion (5) is yours: **does the bridge still behave as an instrument component rather than an
overt resonant effect?** A boundary is only a boundary if what is on the other side of it sounds
different, so the material is at *and* outside the box.

Play **`02_open_chords__range*__cv2_s….wav`**, whole file, against `coupling035` as the reference:

| render | setting | inside the box? | measured elsewhere |
|---|---|---|---|
| `rangeResCeiling` | resonance 330 Hz, damping 0.15, coupling 0.35 | **the worst corner INSIDE it** | 0.770 cents of tuning error, 2.6× inside the ±2-cent gate |
| `rangeResOutside` | resonance 500 Hz, damping 0.15, coupling 0.35 | **outside** | no tuning guarantee; the coupling face fails at ≈0.405 on this corner |
| `rangeDampCeiling` | damping 1.00 | **the ceiling** | 0.03 cents worst over MIDI 21–96 |
| `rangeDampOutside` | damping 4.00 (the slider stop) | **outside** | 7.38 cents, and the worst note migrates to the TOP of the range |
| `rangeCouplingOutside` | coupling 1.00 (the slider stop) | **outside** | −14.06 … +13.41 cents uncompensated across the note scan |

Section RMS, for orientation (dBFS): `rangeResCeiling` −29.17 / −32.68 / −37.64, `rangeResOutside`
−28.65 / −32.07 / −36.99, `rangeDampCeiling` −30.33 / −32.96 / −39.39, `rangeDampOutside` −30.51 /
−33.25 / −39.36, `rangeCouplingOutside` −31.55 / −33.53 / −40.91, for sections A / B / C.

**Pass looks like:** everything inside the box sounds like a guitar with a body; the outside settings
sound like an effect, and the difference is obvious enough that a boundary is worth declaring.
**Fail looks like:** an inside setting that already reads as an effect (the box is too big), or an
outside setting indistinguishable from an inside one (the box is in the wrong place, or too small).
**A "concern" here is legitimate and useful**: it says the box needs re-deriving, which is a P2.9
input rather than a blocker.

### 4.3 The two items that decide code

**Item 17 — is 30 ms of legato glide a hammer-on or a slide?**
Play `03_legato_retrigger__retrigPhysical`, sections B (5.5–9.1 s, ascending) and C (10.0–13.0 s,

## 5. Gain structure — already measured, confirm by ear only

Every corpus render at every rate peaks **below** the `SoftClipLimiter` ceiling. The renderer does
fail the run if one does not — but read that as a tripwire and not as a gate: the limiter is
hard-wired last in the chain and its ceiling is a horizontal asymptote, so a peak above it would mean
the limiter had been bypassed or mis-ordered, which is not something a phrase can cause. **The
headroom column is what the render arrived with, not what the limiter had to take away.** At 48 kHz:

| phrase | peak | headroom below the −0.30 dBFS ceiling |
|---|---|---|
| 01 | −14.00 dBFS | 13.70 dB |
| 02 | −11.16 | 10.86 |
| 03 | −14.80 | 14.50 |
| 04 | −10.96 | 10.66 |
| 05 | −18.14 | 17.84 |
| 06 | −11.14 | 10.84 |
| 07 | −11.43 | 11.13 |
| 08 | −19.87 | 19.57 |

**The −18 dBFS-per-string nominal is INFERRED here, not measured.** `cnpg_render` writes the mono
mix and nothing else, so no number in this table is a per-string level; what the table shows is that
the *sum* of six strings peaks 10.86 dB under the ceiling. The arithmetic is at least consistent with
the nominal — six uncorrelated sources at −18 dBFS sum to −18 + 10·log₁₀6 = **−10.22 dBFS**, against
a measured −11.16 (phrase 02) and −11.14 (phrase 06) — but "consistent with" is not "measured", and
the chain has gain stages between the strings and the output that this arithmetic ignores. Measuring
it properly would mean reading `StringNetwork::tapBuffers()` per string, which is a code change and
not something this session can do. **Record it as an inference if you record it at all.**

**What the numbers cannot tell you is whether the limiter is audibly working**, so item 6 asks for
that by ear on phrase 06.
